# Docker Playground 产品需求文档

**阶段**　MVP 设计评审
**目标用户**　初学 Docker 的开发者、学生，以及需要快速复习命令的用户。

## 1. 产品目标

用户打开网页后，可以在同一个工作区里编写 Dockerfile、构建镜像、运行容器，并从上方的容器列表与下方的终端输出看到操作结果。第一道练习以 5 分钟内完成为设计目标，实际耗时通过试用验证。

首版采用浏览器内模拟，覆盖 Docker 的核心工作流。终端执行预定义命令，容器和镜像由本地状态驱动，构建过程检查受支持的 Dockerfile 指令。真实 Docker、任意 Shell、外网镜像下载、Compose 和端口转发服务属于后续阶段。

## 2. 工作区

| 区域 | 用户操作 | 界面反馈 |
| --- | --- | --- |
| 顶部 · 容器 | 查看容器名称、镜像、状态和端口映射，点击容器查看短 ID 与日志 | 命令执行后立即刷新。状态使用文字与颜色，提供空状态 |
| 中部 · 文件与编辑器 | 在 `/workspace` 新建文件或目录、重命名、删除和编辑。`Ctrl/Cmd+S` 保存 | 文件树与终端共享文件状态。未保存时标记标签，切换文件保留草稿 |
| 底部 · 终端 | 输入命令并回车，上下键浏览历史，使用 `help` 查看支持范围 | 显示命令、标准输出或错误。失败时保留已有资源状态 |
| 右栏 · 练习 | 换题、看提示、检查当前结果 | 按步骤标记通过或待完成，并指出缺少的条件 |
| 右栏 · 命令速查 | 按关键词搜索，浏览语法和例子，将例子填入终端 | 填入后聚焦输入框，由用户回车执行 |

桌面端同时展示四个区域。窄屏按容器、文件、终端的顺序纵向排列，练习与速查通过抽屉打开。容器列表和终端保持独立滚动，命令输入框位于终端底部。

## 3. 首次体验

1. 打开工作区，容器列表为空。文件树包含待编辑的 `Dockerfile` 和示例 `index.html`。
2. 在 Dockerfile 中指定 `FROM nginx:alpine`，再用 `COPY index.html /usr/share/nginx/html/index.html` 将页面加入镜像，保存文件。
3. 在终端运行 `docker build -t my-web .`。构建读取已保存的文件，成功后可用 `docker images` 查到 `my-web:latest`。
4. 运行 `docker run -d --name web -p 8080:80 my-web`。容器列表出现 `web`，镜像为 `my-web:latest`，状态为运行中，映射为 `8080 → 80`。
5. 点击「查看检查结果」。系统检查已保存的 Dockerfile、基于该版本构建的镜像快照和正在运行的容器，逐项给出结果。

## 4. MVP 功能范围

| 功能 | 支持范围 |
| --- | --- |
| Docker 命令 | `docker ps [-a]`、`docker images`、`docker build -t <tag> .`、`docker run -d --name <name> [-p <host>:<container>] <image>`、`docker stop/start/rm/logs <name>` |
| 文件与终端 | `pwd`、`ls [path]`、`cd <path>`、`cat <file>`、`mkdir <dir>`、`touch <file>`、`clear`、`help`。路径限制在虚拟工作区内 |
| Dockerfile | 单阶段 `FROM`、`WORKDIR`、本地单文件 `COPY`、`EXPOSE`、JSON 格式 `CMD`。内置 `nginx:alpine`、`alpine:3.20`；遇到其他镜像、未实现指令或语法错误时给出明确提示 |
| 状态模拟 | 镜像记录构建快照；运行中的容器占用其映射端口；停止后释放端口；重新启动时检查冲突；删除运行中容器时提示先停止 |
| 持久化 | 在当前浏览器中保留文件、未保存草稿、镜像、容器和练习进度。重置工作区需确认后恢复初始内容 |

`EXPOSE` 在模拟中记录镜像端口元数据，`-p` 负责建立容器列表展示的映射。日志为模拟输出。镜像重新打标签或重新构建后，已有容器继续引用创建时的镜像快照。

## 5. 首发练习

| 练习 | 目标 | 检查条件 |
| --- | --- | --- |
| 管理容器生命周期 | 启动 `demo`，查看列表，停止并删除容器 | 记录同一个容器经历运行、停止、删除的有效命令 |
| 构建并运行网页 | 修改 Dockerfile、构建 `my-web` 并运行 `web` | 镜像快照包含目标路径的页面，`web` 使用该镜像运行，映射为 `8080:80` |
| 排查端口冲突 | 处理两个容器争用宿主端口的问题 | 首次运行产生预置冲突，最终两个容器在不同宿主端口运行 |

每道题提供目标、逐步提示和检查结果。判题读取文件、镜像、容器状态与必要的事件记录，接受能达到同一目标的等效操作。切题保留当前工作区；需要预置场景时，提示用户进入独立练习环境，以便保留原有文件。

## 6. 验收标准

- 保存 Dockerfile 后可构建镜像，运行容器后顶部列表即时显示正确镜像与端口，停止后 `docker ps` 隐藏该容器、`docker ps -a` 显示它。
- 缺少 `COPY` 源文件、容器名重复或端口占用时，错误说明具体原因，且不会创建失败的镜像或容器。
- 从文件树创建的文件可在终端读取；使用 `touch` 创建的文件可在编辑器打开。重新加载页面后状态可恢复。
- 速查可搜索 `build`、`端口` 等关键词，插入示例后可先修改再执行。
- 判题能区分当前文件、已构建的文件快照和运行中容器。容器用了旧镜像时，提示用新镜像重新创建容器。
- 编辑、保存、切换练习和执行命令均可用键盘完成。移动端保持终端输入可用，状态可通过文字辨认。

## 7. 试用验证

记录用户能否独立完成首题、从打开页面到首次完成所需时间，以及最常遇到的失败原因。重点观察用户能否理解文件、镜像快照和容器之间的关系，以及遇到错误后能否借助终端和提示恢复。
